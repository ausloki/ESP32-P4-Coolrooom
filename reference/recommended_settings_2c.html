Recommended Settings — 2 °C Coolroom
(All Sensors Online)

ESP32-P4 Coolroom Controller · Profile date 2026-08-03 · Applied live to 192.168.37.237 · Docs: reference/QUICK_START_GUIDE.md

1. Assumptions

  • Target: hold coolroom air at 2.0 °C (commercial food chiller, not a freezer).
  • Plant: single compressor; passive / timed defrost (compressor held off; no heater coil on this controller).
  • Fans: evaporator fans run continuously hardwired — Fan Relay (coil 0) stays disabled / reserved.
  • Sensors online (profile intent): coolroom RTD (Probe 1), evaporator RTD (Probe 2), internal SHT31 humidity/temp, external/ambient SHT20, Modbus relay board, door reed fitted (NC).
  • Priority: safe, stable defaults over aggressive energy saving.
Bench note: On the development bench, RS485 (relay / RTD) and expansion I2C sensors may still be physically disconnected. Enabling those sensors for this profile is correct; Modbus timeouts and “board offline” diagnostics remain expected until the hardware is wired. Cooling end-to-end cannot be proven until RS485 (+ sensors) are attached.

4. Intentionally left at factory default

  • Compressor protection timers (3 / 2 min) — OEM-safe; no reason to shorten.
  • Fan Relay Off — current plant fans are continuous hardwired.
  • Hold Compressor While Door Open Off — stuck-reed risk outweighs benefit until reed is proven reliable.
  • Skip-If-Cold Off — energy optimisation after commissioning, not day-one.
  • Ice / smart thresholds (15 °C, 8 °C, dwells) — start from manual defaults; tune from real frost behaviour.
  • Calibration offsets 0.0 — never invent a correction without a reference thermometer.
  • Home Assistant API — left as found (opt-in; not part of this cooling profile).
  • Firmware YAML initial_values — not changed; shipping factory defaults stay general-purpose.

5. How to re-apply or revert

  • Re-apply from UI: log in on the web dashboard → set the values in the tables above (or follow Quick Start §4 “2 °C food coolroom” worked example).
  • Re-apply via REST (LAN): POST http://<ip>/number/<Name>/set?value=… and …/switch/<Name>/turn_on|turn_off (empty body + Content-Length: 0). Template numbers can take a few seconds to re-publish; globals update immediately and stage to NVS.
  • After ≥30 days of SD logs: optional PC helper tools/analyse_logs_tune_settings.py (Win/mac wrappers) recommends tweaks from events.csv / daily CSVs against this profile — recommend-only by default; see Quick Start §7 and tools/README_LOG_TUNING.md.
  • Verify persistence: reboot (do not use plain USB esphome upload — that erases NVS). Prefer ./tools/esphome_flash.sh or OTA if flashing.
  • Backup: once happy, use Backup All Settings to SD so you can Restore after a factory reset.
  • Full factory defaults: Factory Reset button (erases settings + Wi‑Fi) or flash with --erase-settings.
Disclaimer: Starting values based on general commercial chill practice for ~2 °C food storage and this controller’s documented behaviour. Confirm against your product, local food-safety rules, and how the loaded room actually performs. Humidity is reported only — provide separate humidification if required.
